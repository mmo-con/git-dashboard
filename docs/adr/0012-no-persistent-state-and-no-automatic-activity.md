# ADR 0012: No persistent state and no automatic activity

Status: Accepted, amended by [ADR 0015](0015-showing-incoming-commits.md)

## Context

Several requested features would make headquarters act without an explicit
key or keep data between runs: a persistent status cache with automatic
refresh ([#9](https://github.com/mmo-con/headquarters/issues/9)), a batch
history across restarts
([#15](https://github.com/mmo-con/headquarters/issues/15)), and a periodic
background fetch ([#21](https://github.com/mmo-con/headquarters/issues/21)).
The current behavior was a deliberate property of the design but had not
been recorded, so these features could change it unnoticed.

## Decision

headquarters keeps no state between runs. Inventory, inspection results,
marks, expansion state, recent and incoming commits, and the operations view
live only in memory. Apart from short-lived temporary files, the only file it
writes is the configuration generated by `headquarters init`
([ADR 0009](0009-starting-configuration-generation.md)).

Network access happens only after an explicit key: `f`, `F`, `u`, `U`, or an
interactive retry. Repositories are inspected only:

- when the inventory is loaded, at startup and on `R`;
- for visible repositories on `r`;
- for the stores affected by an operation or a terminal handover
  ([ADR 0005](0005-terminal-handover-and-job-coordination.md));
- for the recent commits of the selected repository
  ([ADR 0003](0003-git-cli-and-process-isolation.md));
- for the incoming commits of the selected repository or row
  ([ADR 0015](0015-showing-incoming-commits.md)).

The configuration is read at startup and on `R`; it is not watched. A
periodic tick only redraws relative times such as fetch ages; it starts no
process.

## Consequences

- Displayed state can be older than the repository after changes by other
  tools; the fetch age and `r` make this visible and fixable.
- No cache can go stale, be corrupted, or leak repository paths and remote
  URLs to disk, and no lock or file is left behind after a crash.
- Background network access can neither prompt for credentials unexpectedly
  nor contend with the user's own Git commands.
- Persistent state, automatic refresh, or automatic fetch each require a new
  ADR that amends or supersedes this one and defines location, format,
  invalidation, and opt-in behavior.
